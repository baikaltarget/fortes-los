## 0а. Что изменилось в v7

- Ключи Telegram добавлены в Vercel — заявки с форм уходят в чат/группу. Как проверить — см. раздел «Как проверить отправку в Telegram» ниже.
- Плашка cookie внизу сайта (появляется один раз, запоминает согласие в localStorage, ссылка на `/politika/`).
- В подвале строка «Разработка сайта — Байкал Таргет» со ссылкой на `baikal-target.ru`.
- Маска телефона `+7 (___) ___-__-__` в формах, кнопка отправки активна только при полных 10 цифрах номера (11 с кодом страны). То же самое проверяется и на сервере в `/api/lead`.
- Скрытое honeypot-поле в формах против ботов: если его заполнили (видно только автозаполнялкам форм, не людям) — заявка не уходит в Telegram, но пользователь/бот видит «успех», чтобы не подсказывать боту, что его поймали. Проверяется и на сервере.
- Подвал: на широких экранах (xl, от ~1280px) 7 колонок вместо 6 — раньше колонка «Компания» переносилась на новую строку и оставляла пустое место справа.

### Как проверить отправку в Telegram
1. Vercel → Settings → Environment Variables — убедиться, что `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` заданы для Production, и был Redeploy после их добавления (без Redeploy новые переменные не подхватятся).
2. Написать боту (тому, чей токен указан) любое сообщение в личку или добавить его в группу — иначе Telegram не даст отправить сообщение в этот чат.
3. Открыть сайт → любая форма заявки → заполнить телефон (маска не даст отправить неполный) → «Получить расчёт».
   - Если пришло сообщение «🟥 Заявка с сайта» с телефоном и страницей — всё работает.
   - Если форма показала «Отправка заявок через сайт ещё не настроена» — значит на Vercel не подхватились переменные (шаг 1) или неверный `TELEGRAM_CHAT_ID`.
4. Дополнительно можно проверить вручную из терминала:
   ```
   curl -X POST https://<ваш-домен>/api/lead/ -H "Content-Type: application/json" \
     -d '{"name":"Тест","phone":"+79161234567","source":"test"}'
   ```
   Ответ `{"ok":true}` — сообщение ушло в Telegram. `{"ok":false,"fallback":true}` — ключи не настроены/не подхватились. `{"ok":false,"error":"phone"}` — неверный формат номера (нужно ровно 11 цифр).
5. Логи неудачных отправок и honeypot-срабатываний — Vercel → Deployments → выбрать деплой → Functions → `/api/lead` → Logs.

## 1. Как опубликовать (≈10 минут)

1. **GitHub** → New repository (например `fortes-septik`, Private) → Create.
2. На странице репозитория → «uploading an existing file» → перетащить **содержимое этой папки** (не саму папку): в корне репозитория должен лежать `package.json`. Commit changes.
3. **vercel.com** → Sign up через GitHub → Add New → Project → Import `fortes-septik` → Deploy. Через 2–3 минуты сайт доступен на `https://fortes-septik-….vercel.app`.
4. Проверить сайт с телефона: кнопка «Позвонить» внизу открывает набор номера.
5. Vercel → Settings → Environment Variables → добавить (см. `.env.example`):
   - `TELEGRAM_BOT_TOKEN` — от @BotFather
   - `TELEGRAM_CHAT_ID` — id чата/группы, куда падают заявки
   - `NEXT_PUBLIC_SITE_URL` — адрес сайта (сначала `*.vercel.app`, после подключения домена — домен)
   После добавления → Deployments → Redeploy. Пока ключей нет, форма честно пишет «не настроено», показывает телефон и кнопку «Написать в Telegram», а заявка попадает в логи Vercel (Deployments → Functions → /api/lead).
6. Домен подключать только после проверки на `*.vercel.app`: Vercel → Settings → Domains.

Если после правки сайт «не обновился»: GitHub → счётчик коммитов вырос? → Vercel → Deployments: статус Building / Ready / Error → в браузере Ctrl+Shift+R.

## 2. Где что править (без кода)

Весь контент — в **`content/site.json`**. Дизайн — в `tailwind.config.ts`, `app/globals.css`, `components/`.

| Что | Где в `site.json` |
|---|---|
| Телефон, email, часы, адреса, реквизиты | `company` |
| Тексты и цены на главной | `home`, `homeFaq`, `reasons`, `steps` |
| Станции: цены, характеристики, FAQ | `products[]` — цена станции `price`, Midi/Long `priceMidi/priceLong`, монтаж от `installFrom` |
| Три хита на главной и в калькуляторе | `topPicks` |
| Страницы-услуги (`/septik-bez-otkachki/` и т.д.) | `services[]` |
| Гео-страницы (`/kanalizaciya/khomutovo/`) | `geo[]` — поле `about` = уникальный текст про посёлок |
| Объекты со сметами | `objects[]` |
| Отзывы | `reviews[]` |
| Надбавки калькулятора | `calculator.extras` |
| Красные рамки-подсказки | `showDraftFrames: true` → поставить `false` перед сдачей |
| Текст cookie-плашки | `components/CookieBar.tsx` (не в JSON — правится в коде) |
| Строка «Разработка сайта» в подвале | `components/Footer.tsx`, последняя строка перед `</footer>` |

Статьи — файлы `content/blog/*.md` (заголовок в шапке файла, текст в Markdown).

### Добавить гео-страницу
В `geo[]` скопировать любой блок, поменять `slug` (латиницей), `name`, `prep` («в Никольске»), `distance`, `soil`, `note`. Дописать `about` (2 абзаца про посёлок). Страница `/kanalizaciya/<slug>/`, sitemap и чипы появятся сами.

### Добавить объект
В `objects[]` скопировать блок, заполнить, положить фото в `public/img/objects/`, указать путь в `images`, поставить `"draft": false`.

### Добавить статью
Создать `content/blog/moya-statya.md` по образцу соседних. Адрес — `/blog/moya-statya/`.

### Добавить станцию
В `products[]` скопировать блок, указать `brand` (`novo-eko` / `zorde` / `kolo-vesi`). Появится в каталоге, на странице бренда, в ценах.
